# Deployment Guide (free tier)

The whole stack runs on free tiers. Every component is open source except the hosted LLM and
embedding API, and both can be swapped for local models (option B).

| Layer | Free option used here | Notes |
|---|---|---|
| Backend (FastAPI + SQLite) | **Render free web service** (Docker, 512 MB) | Defined in `render.yaml`. The disk is ephemeral, so demo data is re-seeded on every cold start (about 10 s). |
| Frontend (Next.js) | **Vercel Hobby** | Root directory `frontend` |
| LLM | **Gemini API** free tier | Any OpenAI-compatible endpoint, set by environment variables |
| Embeddings | **Gemini `gemini-embedding-001`** via `EMBEDDING_BACKEND=api` | Keeps the backend at about 180 MB. Locally the default is the open-source `bge-small` (fastembed). |
| Vector store | SQLite + NumPy, inside the backend | No extra service |

```text
Browser ──> Vercel (Next.js /ai-copilot) ──HTTPS──> Render (FastAPI) ──> Gemini API (chat + embeddings)
                                                       └─ SQLite + vector index (rebuilt at start)
```

> Hugging Face changed its free tier: Docker Spaces now need a PRO subscription. If you have PRO,
> `deploy/huggingface/` still works (`python deploy/huggingface/prepare_space.py <cloned-space>`).

## Option A: Render + Vercel (free)

### 1. Backend on Render

1. Sign in at <https://render.com> with GitHub.
2. Go to **New → Blueprint** and pick this repository. Render reads `render.yaml` and proposes the
   `cbnest-copilot-api` web service (free plan, Docker, health check `/health`).
3. When asked for `LLM_API_KEY`, paste your Gemini key. Every other variable is preset, and
   `JWT_SECRET_KEY` is generated by Render.
4. Click **Apply**. The first build takes about 5–8 minutes. Then check
   `https://cbnest-copilot-api.onrender.com/health` → `{"success": true, ...}` and open `/docs` on
   the same host.

You can also create the service from the dashboard (**New → Web Service** → this repo → Docker,
root directory `backend`, Dockerfile `./Dockerfile.prod`) and copy the variables from `render.yaml`.

### 2. Frontend on Vercel

1. In Vercel go to **Add New → Project** and import this repository. Set **Root Directory** to
   `frontend`.
2. Add the environment variable `NEXT_PUBLIC_API_BASE_URL = https://cbnest-copilot-api.onrender.com`,
   with no trailing slash.
3. Deploy. If you change the variable later, **redeploy**: `NEXT_PUBLIC_*` values are built into
   the bundle.
4. If your Vercel URL is not `https://cbnest-ai-copilot.vercel.app`, update `CORS_ORIGINS` on Render
   (Environment tab). Render redeploys automatically.

### 3. Smoke test

1. Open the Vercel URL and log in as `employee@mock-hrms.dev` / `password123`.
2. Open **AI Copilot** and ask "How many sick leaves do I get?". You should get an answer with
   **Leave Policy** as the source.
3. Log in as `manager@mock-hrms.dev` and ask "Approve Employee User's pending leave request.".
   You should get a **Confirm** card.

### Free-tier behaviour to know

- **Render free services sleep after 15 minutes without traffic.** The next request wakes them,
  which takes about 1 minute (start, seed, index). Open the backend URL a few minutes before a
  live demo.
- **Data resets on every restart** (ephemeral disk). That suits a demo.
- **Gemini free-tier quotas are small.**
  - Chat: `gemini-3.5-flash` has 20 requests/day, so use a `flash-lite` model.
  - Embeddings: 100 texts/minute, and the index uses about 70 at each start; the backend waits
    out rate limits automatically.
  - Rate limits show in the UI as "The AI service is busy…".
- Access tokens last 60 minutes on Render (`ACCESS_TOKEN_EXPIRE_MINUTES`); log in again after that.

## Option B: fully local and fully open source (Docker Compose + Ollama)

No API keys and nothing leaves your machine. Needs about 8 GB of free RAM for the model.

1. Install [Ollama](https://ollama.com) and pull a model that supports tool calling:
   ```bash
   ollama pull qwen2.5:7b
   ```
2. In `backend/.env`:
   ```
   LLM_BASE_URL=http://host.docker.internal:11434/v1
   LLM_MODEL=qwen2.5:7b
   LLM_API_KEY=
   ```
   No key is needed for local endpoints. Use `http://localhost:11434/v1` when running without
   Docker.
3. Start the stack as in the README:
   ```bash
   docker-compose up -d --build
   docker-compose exec api alembic -c alembic.ini upgrade head
   docker-compose exec api python scripts/seed.py
   ```

Smaller local models are noticeably weaker at tool calling than hosted models. The safety layers
(permissions, SQL guardrails, confirmations) do not depend on model quality.

## Production checklist

- [ ] `JWT_SECRET_KEY` is a long random secret, never committed.
- [ ] `LLM_API_KEY` is set only as a host secret.
- [ ] `CORS_ORIGINS` lists only your frontend URL(s).
- [ ] `/health` responds and `/docs` loads.
- [ ] The smoke test above passes for employee and manager.
